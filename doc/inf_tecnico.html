Informe Técnico y Manual de Instalación

Arquitectura, análisis de dependencias, configuración de servidor web Apache en reversa, gestión con PM2, optimización para 8 GB RAM / 512 GB SSD y procedimientos operativos de respaldo en VPS Ubuntu LTS.

Organización Gobernación Norte de Santander
Sitio Principal (Frontend) dha-san.nortedesantander.gov.co
Sitio API (Backend) api-dha-san.nortedesantander.gov.co
Hardware VPS 8 GB RAM / 512 GB SSD / Ubuntu LTS

1. Resumen Ejecutivo del Proyecto

El Sistema de Seguimiento de Indicadores es una solución web institucional diseñada para la Gobernación de Norte de Santander, cuyo objetivo principal es recopilar, consolidar, procesar y visualizar los indicadores misionales de las diferentes secretarías y entidades del departamento, facilitando la toma de decisiones informadas mediante tableros dinámicos, gráficos estadísticos y mapas coropléticos georreferenciados.

Dominio Aplicación Web (SPA)
https://dha-san.nortedesantander.gov.co/

Interfaz de usuario desarrollada en React 18 / Vite 5, servida como compilación estática de alto rendimiento bajo Apache 2.4 con soporte de enrutamiento HTML5.

Dominio API Backend
https://api-dha-san.nortedesantander.gov.co/

API RESTful en Node.js / Express orquestada por PM2 en puerto local 4000, expuesta hacia internet mediante Proxy Reverso Apache seguro.

Certificación Criptográfica SSL Wildcard Activa Ambos sitios web operan con terminación HTTPS empleando el certificado wildcard institucional ya instalado: /etc/ssl/certs/wildcard_nortedesantander_gov_co.crt y su llave privada /etc/ssl/private/wildcard_nortedesantander_gov_co.key, garantizando el cifrado perimetral de extremo a extremo.

2. Arquitectura del Sistema e Infraestructura

La solución se despliega en una arquitectura desacoplada de 3 capas sobre un servidor VPS (Virtual Private Server) exclusivo con sistema operativo Ubuntu LTS:

  1. Capa de Borde y Presentación (Apache HTTP Server 2.4): Actúa como servidor web estático para los artefactos de la SPA React y simultáneamente como terminador SSL y Proxy Reverso HTTP para la API Node.js.
  2. Capa de Aplicación y Lógica de Negocio (Node.js + PM2): Motor de ejecución en tiempo real de la API RESTful (Express), autenticación JWT, orquestación de subida/procesamiento de planillas Excel y consultas analíticas con control de memoria RAM.
  3. Capa de Persistencia (MySQL 8.0 Server): Motor de base de datos relacional InnoDB con soporte nativo de transacciones, integridad referencial en cascada, collation UTF-8 multilingüe e índices optimizados para agregaciones.

La base de datos relacional se denomina gober_indicadores_app y consta de 11 tablas normalizadas con motor InnoDB y juego de caracteres utf8mb4. La estructura está concebida para soportar indicadores dinámicos (dimensiones configurables en tiempo de ejecución sin alterar el esquema físico):

Diagrama 3: Modelo Entidad-Relación (ERD)

Figura 3: Diagrama de Entidad-Relación y cardinalidad de la base de datos gober_indicadores_app.
Diseño Híbrido Flexible (Patrón EAV para Valores de Variables) El modelo implementa el patrón Entity-Attribute-Value entre indicador_registros, indicador_variables e indicador_valores. 5. Configuraciones en Producción

5.1. Configuración de Apache HTTP Server

Apache se encarga de servir los dos dominios independientes con sus correspondientes certificados SSL Wildcard instalados en el sistema.

A) Módulos de Apache Requeridos

Ejecutar los siguientes comandos en el servidor para habilitar los módulos necesarios de proxy reverso, reescritura de URL y seguridad SSL:

Terminal VPS (Bash)
sudo a2enmod ssl
sudo a2enmod proxy
sudo a2enmod proxy_http
sudo a2enmod headers
sudo a2enmod rewrite
sudo a2enmod http2
sudo systemctl restart apache2

B) VirtualHost 1: Frontend SPA (dha-san.nortedesantander.gov.co)

Ubicación: /etc/apache2/sites-available/dha-san.nortedesantander.gov.co.conf

/etc/apache2/sites-available/dha-san.nortedesantander.gov.co.conf
# Redirección HTTP a HTTPS
<VirtualHost *:80>
    ServerName dha-san.nortedesantander.gov.co
    ServerAdmin webmaster@nortedesantander.gov.co

    RewriteEngine On
    RewriteCond %{HTTPS} off
    RewriteRule ^(.*)$ https://%{HTTP_HOST}%{REQUEST_URI} [R=301,L]

    ErrorLog ${APACHE_LOG_DIR}/dha_san_error.log
    CustomLog ${APACHE_LOG_DIR}/dha_san_access.log combined
</VirtualHost>

# Sitio Principal HTTPS
<VirtualHost *:443>
    ServerName dha-san.nortedesantander.gov.co
    ServerAdmin webmaster@nortedesantander.gov.co
    DocumentRoot /var/www/indicadores/frontend/dist

    # Certificados SSL Wildcard Instalados
    SSLEngine on
    SSLCertificateFile /etc/ssl/certs/wildcard_nortedesantander_gov_co.crt
    SSLCertificateKeyFile /etc/ssl/private/wildcard_nortedesantander_gov_co.key

    # Protocolos y Cifrados Seguros
    SSLProtocol all -SSLv3 -TLSv1 -TLSv1.1
    SSLCipherSuite ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384
    SSLHonorCipherOrder on

    # Cabeceras de Seguridad
    Header always set X-Frame-Options "SAMEORIGIN"
    Header always set X-XSS-Protection "1; mode=block"
    Header always set X-Content-Type-Options "nosniff"
    Header always set Referrer-Policy "strict-origin-when-cross-origin"
    Header always set Strict-Transport-Security "max-age=31536000; includeSubDomains"

    <Directory /var/www/indicadores/frontend/dist>
        Options -Indexes +FollowSymLinks
        AllowOverride All
        Require all granted

        # Soporte para Enrutamiento HTML5 SPA de React Router
        RewriteEngine On
        RewriteBase /
        RewriteRule ^index\.html$ - [L]
        RewriteCond %{REQUEST_FILENAME} !-f
        RewriteCond %{REQUEST_FILENAME} !-d
        RewriteRule . /index.html [L]
    </Directory>

    # Compresión GZIP / Deflate para máximo rendimiento
    AddOutputFilterByType DEFLATE text/html text/plain text/xml text/css application/javascript application/json

    ErrorLog ${APACHE_LOG_DIR}/dha_san_ssl_error.log
    CustomLog ${APACHE_LOG_DIR}/dha_san_ssl_access.log combined
</VirtualHost>

C) VirtualHost 2: Backend API (api-dha-san.nortedesantander.gov.co)

Ubicación: /etc/apache2/sites-available/api-dha-san.nortedesantander.gov.co.conf

/etc/apache2/sites-available/api-dha-san.nortedesantander.gov.co.conf
# Redirección HTTP a HTTPS
<VirtualHost *:80>
    ServerName api-dha-san.nortedesantander.gov.co
    ServerAdmin webmaster@nortedesantander.gov.co

    RewriteEngine On
    RewriteCond %{HTTPS} off
    RewriteRule ^(.*)$ https://%{HTTP_HOST}%{REQUEST_URI} [R=301,L]

    ErrorLog ${APACHE_LOG_DIR}/api_dha_san_error.log
    CustomLog ${APACHE_LOG_DIR}/api_dha_san_access.log combined
</VirtualHost>

# API REST HTTPS - Proxy Reverso hacia PM2 Node.js (:4000)
<VirtualHost *:443>
    ServerName api-dha-san.nortedesantander.gov.co
    ServerAdmin webmaster@nortedesantander.gov.co

    # Certificados SSL Wildcard Instalados
    SSLEngine on
    SSLCertificateFile /etc/ssl/certs/wildcard_nortedesantander_gov_co.crt
    SSLCertificateKeyFile /etc/ssl/private/wildcard_nortedesantander_gov_co.key

    SSLProtocol all -SSLv3 -TLSv1 -TLSv1.1
    SSLCipherSuite HIGH:!aNULL:!MD5:!3DES

    # Control de límite de carga en el servidor web (25 MB para planillas Excel)
    LimitRequestBody 26214400

    # Configuración de Proxy Reverso hacia Node en puerto 4000
    ProxyPreserveHost On
    ProxyRequests Off

    RequestHeader set X-Forwarded-Proto "https"
    RequestHeader set X-Forwarded-Port "443"

    ProxyPass / http://127.0.0.1:4000/ retry=1 acquire=3000 timeout=600 Keepalive=On
    ProxyPassReverse / http://127.0.0.1:4000/

    # Cabeceras de Seguridad
    Header always set X-Content-Type-Options "nosniff"

    ErrorLog ${APACHE_LOG_DIR}/api_dha_san_ssl_error.log
    CustomLog ${APACHE_LOG_DIR}/api_dha_san_ssl_access.log combined
</VirtualHost>

5.3. Configuración del Gestor de Procesos PM2 con Límite de Memoria

Para el servidor con 8 GB de RAM, se configura PM2 en modo clúster con límite de memoria preventiva (max_memory_restart: "1G") y el flag de Node.js --max-old-space-size=1536 (1.5 GB de Heap máximo) para procesar planillas Excel grandes sin riesgo de desbordar la memoria del servidor:

/var/www/indicadores/backend/ecosystem.config.cjs
module.exports = {
  apps: [
    {
      name: "indicadores-api",
      script: "src/app.js",
      cwd: "/var/www/indicadores/backend",
      instances: "max",       // Aprovecha los núcleos de CPU disponibles
      exec_mode: "cluster",
      max_memory_restart: "1G", // Reinicio suave si el proceso supera 1 GB
      node_args: "--max-old-space-size=1536", // Limita el Heap V8 a 1.5 GB
      watch: false,
      env: {
        NODE_ENV: "production",
        PORT: 4000
      },
      error_file: "/var/log/pm2/indicadores_err.log",
      out_file: "/var/log/pm2/indicadores_out.log",
      time: true
    }
  ]
};

5.5. Ajuste y Optimización de Rendimiento para el VPS (8 GB RAM / 512 GB SSD)

Al disponer de 8 GB de memoria RAM y almacenamiento SSD de 512 GB, se debe configurar el motor MySQL y el pool de conexiones de Node.js para maximizar la velocidad de respuesta sin comprometer la estabilidad del sistema operativo:

A) Calibración de MySQL 8.0 (/etc/mysql/mysql.conf.d/mysqld.cnf)

Se recomienda asignar el 50% al 60% de la memoria física (4 GB) al innodb_buffer_pool_size, garantizando que los índices y datos de las 11 tablas residan en memoria RAM de alta velocidad:

/etc/mysql/mysql.conf.d/mysqld.cnf (Fragmento a agregar o modificar)
[mysqld]
# Asignación de memoria para InnoDB (50% de los 8 GB de RAM)
innodb_buffer_pool_size = 4G
innodb_buffer_pool_instances = 4
innodb_log_file_size = 512M
innodb_log_buffer_size = 64M
innodb_flush_log_at_trx_commit = 2   # Alto rendimiento en escrituras con disco SSD
innodb_flush_method = O_DIRECT

# Conexiones simultáneas y cachés
max_connections = 150
table_open_cache = 4000
tmp_table_size = 64M
max_heap_table_size = 64M
thread_cache_size = 50

# Seguridad de red: escuchar únicamente en localhost
bind-address = 127.0.0.1

Aplicar cambios reiniciando el servicio:

sudo systemctl restart mysql

B) Calibración del Pool de Conexiones en Node.js (backend/src/config/db.js)

Para sincronizarse armónicamente con las instancias de PM2 y la capacidad de MySQL, el pool de conexiones debe parametrizarse así:

backend/src/config/db.js (Configuración recomendada)
const mysql = require('mysql2/promise');
require('dotenv').config();

const pool = mysql.createPool({
    host: process.env.DB_HOST || 'localhost',
    user: process.env.DB_USER || 'root',
    password: process.env.DB_PASSWORD || '',
    database: process.env.DB_NAME || 'gober_indicadores_app',
    waitForConnections: true,
    connectionLimit: 25,     // Ajustado para soportar múltiples workers de PM2
    queueLimit: 0,
    connectTimeout: 10000,
    enableKeepAlive: true,
    keepAliveInitialDelay: 10000
});

module.exports = pool;

C) Control y Limitación de Memoria RAM para Archivos Pesados

Para evitar que planillas Excel con miles de filas saturen la memoria RAM del servidor VPS durante la carga masiva, se aplican tres barreras de protección concurrentes:

  1. Barrera Perimetral Apache: Directiva LimitRequestBody 26214400 (25 MB) en el VirtualHost de la API para rechazar peticiones sobrecargadas antes de ingresar al runtime.
  2. Barrera de Middleware Express (Multer): Parámetro de control de tamaño en la ruta de carga: 
    const upload = mult({
    storage: mult.memoryStorage(),
    limits: { fileSize: 25 * 1024 * 1024 } // 25 MB máximo por archivo
});
  3. Barrera del Motor V8 (PM2): Parámetro node_args: "--max-old-space-size=1536" en ecosystem.config.cjs, que previene que la recolección de basura de Node colapse el servidor operativo.

6. Guía de Instalación Paso a Paso en VPS Ubuntu Limpio

Esta guía describe la puesta en marcha completa y desde cero en un servidor virtual privado exclusivo con Ubuntu LTS (22.04 / 24.04), 8 GB de RAM y 512 GB SSD.

  1. Actualización del Sistema y Paquetes Base

    Actualice los repositorios del sistema e instale utilidades de red y compilación:

    sudo apt update && sudo apt upgrade -y
sudo apt install -y curl wget git build-essential ufw htop unzip software-properties-common

  2. Instalación de Node.js (v18 LTS) y PM2

    Configure el repositorio oficial de NodeSource para obtener la versión LTS adecuada:

    # Instalar NodeSource LTS (v18.x)
curl -fsSL https://deb.nodesource.com/setup_18.x | sudo -E bash -
sudo apt install -y nodejs

# Verificar versiones
node -v   # Debe mostrar v18.x
npm -v    # Debe mostrar v10.x

# Instalar PM2 de forma global y módulo de rotación de logs
sudo npm install -g pm2
sudo pm2 install pm2-logrotate
sudo pm2 set pm2-logrotate:max_size 15M
sudo pm2 set pm2-logrotate:retain 10

  3. Instalación y Securización de MySQL Server 8.0

    Instale el servidor de base de datos y ejecute el asistente de endurecimiento:

    sudo apt install -y mysql-server
sudo mysql_secure_installation

    Acceda a la consola de MySQL, cree la base de datos y el usuario de servicio con privilegios específicos:

    sudo mysql -u root

-- Dentro de MySQL:
CREATE DATABASE gober_indicadores_app CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER 'indicadores_user'@'localhost' IDENTIFIED BY 'ClaveRobustaSegura2026!';
GRANT ALL PRIVILEGES ON gober_indicadores_app.* TO 'indicadores_user'@'localhost';
FLUSH PRIVILEGES;
EXIT;

    Aplique los parámetros de optimización para 8 GB de RAM en /etc/mysql/mysql.conf.d/mysqld.cnf (sección 5.5) y reinicie el servicio:

    sudo systemctl restart mysql

  4. Despliegue y Preparación del Código en el Servidor

    Cree el directorio de aplicaciones y clone o transfiera el repositorio:

    sudo mkdir -p /var/www/indicadores
sudo chown -R $USER:$USER /var/www/indicadores
cd /var/www/indicadores

# Clonar el proyecto (o transferir via SCP/Git)
git clone <URL_DEL_REPOSITORIO> .

# Configurar permisos para Apache y ejecución
sudo chown -R www-data:www-data /var/www/indicadores
sudo chmod -R 755 /var/www/indicadores

  5. Puesta en Marcha del Backend (Node.js API)

    Instale dependencias del backend, configure variables y levante el servicio con PM2:

    cd /var/www/indicadores/backend

# Instalar dependencias excluyendo las de desarrollo
npm install --omit=dev

# Configurar variables de producción
nano .env
# (Asignar las credenciales creadas para MySQL y las claves seguras de producción)
chmod 600 .env

# Crear directorio de logs de PM2
sudo mkdir -p /var/log/pm2
sudo chown -R $USER:$USER /var/log/pm2

# Iniciar aplicación con PM2
pm2 start ecosystem.config.cjs

# Guardar configuración y habilitar inicio con el sistema
pm2 save
sudo env PATH=$PATH:/usr/bin pm2 startup systemd -u $USER --hp /home/$USER

  6. Compilación y Publicación del Frontend (React Vite)

    Instale paquetes y compile los bundles estáticos para producción:

    cd /var/www/indicadores/frontend

# Configurar variable de API para producción ANTES de compilar
echo "VITE_API_URL=https://api-dha-san.nortedesantander.gov.co/api" > .env.production

# Instalar y compilar
npm install
npm run build

# Verificar que la carpeta dist contenga index.html y assets
ls -la dist/

  7. Instalación y Configuración de Apache 2.4 con SSL

    Instale el servidor web Apache, verifique los certificados SSL Wildcard y active los dos VirtualHosts:

    sudo apt install -y apache2

# Verificar que los certificados SSL Wildcard institucionales existan en:
# /etc/ssl/certs/wildcard_nortedesantander_gov_co.crt
# /etc/ssl/private/wildcard_nortedesantander_gov_co.key

sudo chmod 600 /etc/ssl/private/wildcard_nortedesantander_gov_co.key
sudo chmod 644 /etc/ssl/certs/wildcard_nortedesantander_gov_co.crt

# Crear los archivos de VirtualHost con las configuraciones del punto 5.1
sudo nano /etc/apache2/sites-available/dha-san.nortedesantander.gov.co.conf
sudo nano /etc/apache2/sites-available/api-dha-san.nortedesantander.gov.co.conf

# Habilitar módulos, sitios y deshabilitar sitio por defecto
sudo a2enmod ssl proxy proxy_http headers rewrite http2
sudo a2ensite dha-san.nortedesantander.gov.co.conf
sudo a2ensite api-dha-san.nortedesantander.gov.co.conf
sudo a2dissite 000-default.conf

# Validar sintaxis de configuración de Apache

7. Estrategia y Procedimiento de Copias de Seguridad

En el servidor VPS, las copias de seguridad de la base de datos gober_indicadores_app y de las configuraciones sensibles se almacenan en el almacenamiento local del servidor (en el disco SSD de 512 GB) en la ruta /var/backups/indicadores/.

Periodicidad actual: El esquema operativo está programado para ejecutarse cada 8 días. No obstante, la frecuencia es totalmente parametrizable (diaria, semanal, cada 8 días o mensual) ajustando la expresión del programador crontab.

7.1. Script Automatizado de Respaldo

Crear el script en /opt/scripts/backup_indicadores.sh con permisos de ejecución:

/opt/scripts/backup_indicadores.sh
#!/bin/bash
# ==============================================================================
# SCRIPT DE RESPALDO - SISTEMA DE INDICADORES DHA-SAN
# GOBERNACIÓN DE NORTE DE SANTANDER
# ==============================================================================

set -e

# Configuración
BACKUP_DIR="/var/backups/indicadores"
DATE=$(date +"%Y%m%d_%H%M%S")
DB_NAME="gober_indicadores_app"
DB_USER="indicadores_user"
DB_PASS="ClaveRobustaSegura2026!"
DAYS_TO_KEEP=60 # Retención de copias en el disco SSD (ej. 60 días)

mkdir -p "${BACKUP_DIR}/db"
mkdir -p "${BACKUP_DIR}/configs"

echo "[$(date)] Iniciando respaldo de base de datos..."
# Volcado consistente sin bloquear lecturas (InnoDB)
mysqldump --single-transaction \
          --quick \
          --routines \
          --triggers \
          -u "${DB_USER}" \
          -p"${DB_PASS}" \
          "${DB_NAME}" | gzip -9 > "${BACKUP_DIR}/db/${DB_NAME}_${DATE}.sql.gz"

echo "[$(date)] Respaldando archivos de configuración sensibles..."
tar -czf "${BACKUP_DIR}/configs/config_${DATE}.tar.gz" \
    /var/www/indicadores/backend/.env \
    /var/www/indicadores/backend/ecosystem.config.cjs \
    /etc/apache2/sites-available/dha-san.nortedesantander.gov.co.conf \
    /etc/apache2/sites-available/api-dha-san.nortedesantander.gov.co.conf 2>/dev/null || true

# Asignar permisos estrictos al respaldo
chmod 600 ${BACKUP_DIR}/db/*
chmod 600 ${BACKUP_DIR}/configs/*

echo "[$(date)] Purgando copias antiguas (más de ${DAYS_TO_KEEP} días)..."
find "${BACKUP_DIR}/db" -type f -name "*.sql.gz" -mtime +${DAYS_TO_KEEP} -exec rm -f {} \;
find "${BACKUP_DIR}/configs" -type f -name "*.tar.gz" -mtime +${DAYS_TO_KEEP} -exec rm -f {} \;

echo "[$(date)] Respaldo completado exitosamente: ${BACKUP_DIR}/db/${DB_NAME}_${DATE}.sql.gz"

Otorgar permisos de ejecución al script:

Terminal VPS (Bash)
sudo chmod +x /opt/scripts/backup_indicadores.sh

7.2. Programación en Crontab (Configuración Cada 8 Días o Ajustable)

Para ejecutar el respaldo cada 8 días a las 02:00 AM, editar la tabla de tareas cron del usuario root:

Terminal VPS (Bash)
sudo crontab -e

# Opción A: Ejecución cada 8 días a las 02:00 AM
0 2 */8 * * /opt/scripts/backup_indicadores.sh >> /var/log/backup_indicadores.log 2>&1

# Opción B (Alternativa sugerida): Ejecución todos los domingos a las 02:00 AM
# 0 2 * * 0 /opt/scripts/backup_indicadores.sh >> /var/log/backup_indicadores.log 2>&1

# Opción C (Alternativa sugerida): Ejecución diaria a las 02:00 AM
# 0 2 * * * /opt/scripts/backup_indicadores.sh >> /var/log/backup_indicadores.log 2>&1

7.3. Recomendación Crucial: Copias de Seguridad Fuera del Servidor (Off-Site)

Riesgo de Copia Única en el Disco Local del VPS: Actualmente los backups quedan en una carpeta del mismo disco SSD del VPS (512 GB). Si bien el espacio en disco es holgado, ante un incidente crítico del proveedor de nube (corrupción de volumen hipervisor, borrado accidental o daño catastrófico de la máquina virtual), se perderían simultáneamente los datos operativos y los respaldos.

Se recomienda encarecidamente implementar la regla de oro 3-2-1 (al menos 3 copias, en 2 medios distintos, con 1 copia fuera del sitio). A continuación se presentan dos métodos automáticos y seguros para replicar las copias fuera del VPS:

Método 1: Sincronización Remota vía SSH/SFTP (Servidor NAS o Almacenamiento Institucional)

Agregar una línea al final de /opt/scripts/backup_indicadores.sh para transferir el archivo recién generado mediante rsync o scp utilizando llaves SSH sin contraseña:

Script de Sincronización Externa (Bash)
# Transferencia segura hacia servidor de respaldo externo
rsync -avz -e "ssh -i /root/.ssh/id_backup_key" \
    "${BACKUP_DIR}/db/${DB_NAME}_${DATE}.sql.gz" \
    usuario_backup@nas.nortedesantander.gov.co:/almacenamiento/backups_dha_san/

Método 2: Sincronización a Bucket de Nube (AWS S3, MinIO o Almacenamiento Compatible)

Empleando la herramienta rclone o aws-cli:

# Enviar a repositorio de objetos institucional
rclone copy "${BACKUP_DIR}/db/${DB_NAME}_${DATE}.sql.gz" remote_institucional:dha-san-backups/

7.4. Procedimiento de Restauración y Recuperación ante Desastres (Disaster Recovery)

Si se requiere restaurar la base de datos a un punto específico en el tiempo, ejecute los siguientes pasos ordenados:

  1. Detenga temporalmente el servicio Node para evitar lecturas/escrituras concurrentes: 
    pm2 stop indicadores-api
  2. Descomprima e ingeste el archivo .sql.gz seleccionado directamente en MySQL: 
    gunzip < /var/backups/indicadores/db/gober_indicadores_app_AAAAMMDD_HHMMSS.sql.gz | mysql -u indicadores_user -p gober_indicadores_app
  3. Reinicie el servicio API en PM2: 
    pm2 start indicadores-api
  4. Compruebe la integridad de la restauración visualizando el estado con pm2 logs y probando el inicio de sesión y los dashboards en el navegador web.

8. Recomendaciones de Despliegue y Administración para el Instalador

Para el personal de soporte, DevOps o administradores de sistemas que configuren o gestionen el sistema en el VPS, se detallan las directrices y buenas prácticas operativas:

1. Manejo y Aislamiento de Credenciales Sensibles en Producción
  • Las claves maestras de base de datos y llaves JWT de producción únicamente deben residir en /var/www/indicadores/backend/.env.
  • El archivo .env debe contar exclusivamente con permisos de lectura para el usuario de ejecución (chmod 600).
  • Nunca almacenar contraseñas en texto claro dentro de scripts compartidos ni subirlos al control de versiones Git.
2. Control de Consumo de Memoria RAM para Procesamiento de Planillas
  • Dado que la importación de datos se realiza mediante subida de archivos Excel analizados con la librería xlsx, se deben mantener activas las tres barreras de protección (límite en Apache 25MB, límite en Multer y límite de Heap V8 en PM2 con --max-old-space-size=1536).
  • Estas directivas evitan que cargas voluminosas de datos de múltiples secretarías simultáneas saturen la memoria RAM de 8 GB del VPS.
3. Política de CORS y Encabezados de Seguridad Perimetrales
  • El backend en backend/src/app.js valida dinámicamente los orígenes permitidos. Mantener la restricción a https://dha-san.nortedesantander.gov.co y subdominios institucionales de la Gobernación.
  • Las cabeceras HSTS (HTTP Strict Transport Security), X-Frame-Options y X-Content-Type-Options configuradas en el VirtualHost de Apache aseguran la máxima calificación en auditorías de ciberseguridad.
4. Mantenimiento y Rotación Preventiva de Logs
  • Los logs de PM2 (/var/log/pm2/) y de Apache (/var/log/apache2/) deben estar sujetos a rotación automática mediante pm2-logrotate y el servicio logrotate nativo de Ubuntu, asegurando que el disco SSD de 512 GB no acumule gigabytes de registros históricos sin comprimir.

9. Lista de Verificación Previa a la Ejecución (Pre-Flight Checklist)

Antes de iniciar o reiniciar los proyectos en el servidor de producción, el administrador debe validar que se cumpla cada uno de los siguientes puntos:

1. Certificados SSL Wildcard Válidos y Accesibles

Verificar que /etc/ssl/certs/wildcard_nortedesantander_gov_co.crt y /etc/ssl/private/wildcard_nortedesantander_gov_co.key existan y tengan permisos 644 y 600 respectivamente.

2. Configuración de Variables de Entorno del Backend

Comprobar que /var/www/indicadores/backend/.env contenga los valores de producción correctos (puerto 4000, credenciales MySQL de producción y secretos JWT de alta entropía).

3. Variable de API Inyectada en el Frontend Antes del Build

Asegurarse de que frontend/.env.production contenga VITE_API_URL=https://api-dha-san.nortedesantander.gov.co/api antes de ejecutar npm run build.

4. Calibración de MySQL 8.0 Aplicada

Verificar que innodb_buffer_pool_size = 4G esté activo en /etc/mysql/mysql.conf.d/mysqld.cnf y que el servicio esté corriendo (systemctl status mysql).

5. Sintaxis de Apache Correcta

Ejecutar sudo apache2ctl configtest y corroborar que devuelva Syntax OK antes de recargar el servidor web.

6. Proceso PM2 Iniciado con Límites de Memoria

Verificar mediante pm2 status que el servicio indicadores-api esté en estado online y con el flag --max-old-space-size=1536 en ejecución.

7. Tarea Programada de Backup Verificada

Ejecutar manualmente sudo /opt/scripts/backup_indicadores.sh para comprobar que genera el archivo .sql.gz correctamente y verificar su registro en el crontab.
